Install on macOS

blitcp copies folders to another drive, a NAS, another machine or cloud storage, and checks that they arrived. On a Mac it comes as a desktop app or as a single command-line file: no installer and no Python needed.

Step 1 — which Mac do you have?

Apple menu → About This Mac shows the chip. In a terminal, uname -m prints arm64 on Apple silicon and x86_64 on Intel.

Step 2 — open it

The app

  1. Double-click the downloaded .zip to unpack it.
  2. Drag the app into Applications.
  3. Open it. The app is notarized by Apple, so the first launch shows macOS's usual question about opening an app downloaded from the internet — click Open. It does not ask again.

The CLI

A browser saves downloads without the executable bit. In Terminal, in the folder you downloaded to:

chmod +x blitcp-macos-arm64
./blitcp-macos-arm64 --help

On an Intel Mac the file is blitcp-macos-intel.

Step 3 — verify your download (optional)

Check the SHA-256

shasum -a 256 blitcp-macos-arm64

Compare the output with the digest below. If it matches, the file on your disk is byte for byte the file from the release; if it does not, delete it and download it again from GitHub.

Or — with Python

pip install blitcp

If you already have Python 3.8 or newer. The quotes matter in zsh, the default shell on macOS:

pip install blitcp           # the CLI
pip install "blitcp[gui]"    # the desktop app
pip install paramiko         # optional: SSH
pip install "blitcp[cloud]"  # optional: S3, Azure, GCS, SMB

Step 4 — your first copy

./blitcp-macos-arm64 ~/Pictures /Volumes/Backup/Pictures

Source first, destination second. Nothing in the source is modified, verification runs by default, and blitcp refuses to start if the destination is too small. More in the local copies guide and the CLI reference.
