Offload camera cards to two drives, verified

You come back with a full card. Before it goes back in the camera and gets formatted, the footage should exist in two places — and you should know both copies are intact, not hope so. blitcp copies the card and reads every file back to check it. Who blitcp is for →

Today: one run per drive

With the current release (v4.2.15), copy the card to each drive in turn. In the desktop app, pick the card as the source and the first drive as the destination, then repeat for the second. From the command line, source first and destination second:

blitcp /media/CARD01 /mnt/shuttle/CARD01
blitcp /media/CARD01 /mnt/archive/CARD01

Each run is checked on its own: every file is read back from the drive and hash-checked against the card. Run it again after the next shoot and files already on the drive are skipped. Nothing on the card is modified or deleted.

Before you format the card

  • Both runs finished and said so. The summary at the end of each run reports what was verified; a file it could not confirm is named there and the run exits with an error.
  • The drive had room. blitcp works out the real size first and refuses to start rather than stopping halfway — so a run that did not start is a run you know about.

From blitcp 4.4.0: both drives in one pass

Coming in v4.4.0, not yet released. The card is read once and written to both drives at the same time, each one checked, with a manifest kept on each drive so the next card only adds what is new. Clip names that a camera reuses from card to card are kept and reported rather than silently overwritten.

blitcp /media/CARD01 --dest /mnt/shuttle --dest /mnt/archive

Questions

How do I know a copy of the card is good?

blitcp checks it for you: after a local copy, every file is read back from the drive and hash-checked against the card. A run that could not confirm a file says so and ends with an error exit code, instead of reporting success.

Can blitcp write the card to two drives at once?

Not in the current release (4.2.15): run it once per drive. blitcp 4.4.0 adds --dest, which reads the card once and writes every destination at the same time, each one checked.

What if I copy the same card again?

Files already on the drive are skipped, so the second run only copies what is new. Nothing on the card is changed or deleted by blitcp — formatting the card stays your decision.

Does it work on a Mac, Windows and Linux?

Yes. blitcp runs on all three, as a desktop app where you pick the card and the drive, or as a command for a script.
