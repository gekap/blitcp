blitcp vs Robocopy

blitcp is an open-source copy tool — CLI and desktop app — that moves a folder to another drive, a NAS, another machine or cloud storage and verifies every file arrived. Robocopy ships with Windows and is built for mirroring. Here is where each one wins.

Use blitcp when

It is a one-way copy you want verified — every file read back from the destination and compared, which robocopy does not do at all.

Use Robocopy when

You need mirroring or retry semantics: /MIR to make the destination match the source including deletions, /R and /W for flaky shares, or a scheduled job on a machine where nothing may be installed. blitcp has none of these, and robocopy ships with Windows.

The measured difference

Windows 11, USB HDD to internal SSD (NTFS), full reboot before each run, standby list purged with RAMMap, Windows Defender active for all tools:

ToolTimeVerifies output?
blitcp2 m 28 syes — every file, by hash
robocopy /MT:13 m 16 sno
robocopy /MT:83 m 44 sno

Note the /MT:8 result: more threads made robocopy slower— 3:44 against 3:16 at /MT:1. The source is a USB 2.0 external drive, so the link is already saturated by a single reader; adding seven more only makes the heads seek between eight interleaved streams. Parallelism helps when a device can serve more requests than one thread can issue, and this one cannot.

What blitcp gave up to post 2:28. It ran --no-dedup --no-cache, so neither deduplication nor the cross-run hash cache contributed anything, and verification was left on — every file read back from the destination and compared. robocopy verifies nothing, and the FastCopy run in the same table used /verify=FALSE. This is blitcp with its own advantages switched off and its integrity check switched on, against tools running without one. The run — 9,578 files / 890.8 MB, USB 2.0 → SSD

Robocopy on Linux and macOS?

Robocopy is part of Windows (Microsoft's reference) and is not available for Linux or macOS. The usual answer there is rsync, which covers the mirroring side — see blitcp vs rsync. If what you used Robocopy for was a one-way copy of a large folder, blitcp does that on all three systems with the same command:

  • One tool on every machine. The same CLI and desktop app on Linux, macOS and Windows, so a script written for one does not need rewriting for another.
  • Verification Robocopy does not do. After a local copy every file is read back from the destination and compared with the source.
  • Copies to Linux machines and NAS boxes over SSH, and to S3, Azure and Google Cloud Storage, besides local and SMB paths.

What does not carry over is /MIR and the /R / /W retry options: blitcp has no mirroring mode and no retry settings.

When Robocopy is still the better tool

Honest answer: when you cannot install anything — locked-down servers, scheduled tasks on machines you don't control — robocopy's zero-install advantage is real. Its /MIR mirroring with attribute filters and its retry/wait semantics (/R /W) for flaky network shares are also mature and battle-tested. If those are your constraints, keep robocopy; if raw speed and verified output matter more, that is what blitcp is for.

Questions

Is Robocopy available on Linux or macOS?

No. Robocopy is a command that ships with Windows. blitcp runs natively on Linux, macOS and Windows, as a command-line tool and as a desktop app, so the same copy job works on all three.

When should I still use Robocopy?

When you need /MIR mirroring that also deletes, /R and /W retries for flaky shares, or a scheduled job on a machine where nothing may be installed. blitcp has none of these, and Robocopy is already part of Windows.

Does Robocopy verify what it copied?

No. blitcp reads every copied file back from the destination and compares it with the source by default. In the Windows benchmark it did so and still finished in 2m28s, against 3m16s for robocopy /MT:1.

Is blitcp free for commercial use?

Yes. blitcp is open source under the Apache-2.0 license, which allows commercial use, and there is no paid tier: the CLI and the desktop app are the whole tool.
