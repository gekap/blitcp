What are you copying with today?

Head-to-head pages with measured, reproducible numbers — no synthetic marketing benchmarks, and every page includes an honest “when the other tool is better” section. Full methodology lives on the benchmarks page.

vs rsync

1.7× faster

8.19s vs 14.14s — 12,347 small files, cold cache, HDD → SSD.

rsync still wins for repeated incremental syncs and anything needing deletes.

Read comparison →

vs cp

2.5× faster

12,347 small files on a rotational disk: physical read ordering, plus reflinks on the same volume.

cp is fine — and already installed — for a handful of files on NVMe.

Read comparison →

vs scp / SFTP

Level over SSH on a 1.1 GB tree; scp ahead to a Windows drive. Separately, 91,663 files pushed in 2m07s — 888 MB of tree, 509.8 MB on the wire after dedup, and blitcp's time only.

scp is faster to a network share or Windows drive, and wins outright on a locked-down gateway with no exec channel.

Read comparison →

vs Robocopy

Verify on, still ahead

2m28s vs 3m16s (/MT:1) — 9,578 files / 890.8 MB, USB 2.0 → SSD. blitcp ran with dedup and its cache OFF and verification ON; robocopy verifies nothing.

Robocopy has mirroring and retry semantics blitcp does not, and ships with Windows.

Read comparison →See the run on /benchmarks/ →

vs FastCopy

Verify on, still ahead

2m28s vs 3m38s — the same 9,578 files / 890.8 MB, USB 2.0 → SSD run. blitcp had dedup and cache OFF and verification ON; FastCopy ran /verify=FALSE.

FastCopy is Windows-only but very tunable if you like knobs.

Read comparison →See the run on /benchmarks/ →

vs TeraCopy

6 min ahead

19m06s verify-on vs 25m20s verify-off — 11,878 files / 11.4 GB mixed.

TeraCopy integrates into the Explorer right-click menu, which blitcp does not.

Read comparison →
