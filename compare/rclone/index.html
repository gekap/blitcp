blitcp vs rclone

blitcp is an open-source copy tool — CLI and desktop app — that moves a folder to another drive, a NAS, another machine or cloud storage and verifies it arrived. rclone is a command-line tool that reaches over 70 cloud storage products as well as the local filesystem and SFTP rclone.org. They overlap on local, SSH and S3-style copies; outside that overlap they are different tools. Here is where each one fits.

Use blitcp when

The copy goes to a local drive, a NAS or another machine over SSH, and you want it read in disk order and verified, from a native desktop app or one command — with nothing but ssh and tar needed on the far side.

Use rclone when

You work with cloud services through their own API — Google Drive, OneDrive, Dropbox and the rest of its 70-plus providers — or you need sync with deletes, a remote mounted as a disk, or server-side copies within one provider.

What blitcp is built around

These are the parts of blitcp's design that matter most for local and SSH copies. They are listed for what they do, not as a claim about rclone:

  • Reading in disk order. Files are read in the order their data sits on the disk, which removes most of the seeking on a spinning drive. The small-file benchmark against rsync.
  • One tar stream over plain SSH. Nothing to install on the server, and no SFTP needed — BusyBox and Synology boxes work.
  • Duplicates stored once. Identical files become hard links or reflinks at the destination, and a cache carries the hashes across runs.
  • A pre-flight space check. blitcp works out the real size first and refuses to start if the destination is too small.
  • Sparse files and VM images copied at their allocated size — the sparse-files guide.

Speed

There is no blitcp-against-rclone measurement, so this page makes no speed claim. Every comparison that has been measured is on the benchmarks page, with its commands.

When rclone is the better tool

When the other end is a cloud service and you want to talk to it directly: rclone lists over 70 cloud storage products, including Google Drive, OneDrive and Dropbox through their APIs rclone.org. Also when you need a destination kept identical to the source, deletions included (rclone sync rclone.org), a remote mounted as a disk rclone.org, or a copy between two buckets of one provider done server-side, without downloading and re-uploading rclone.org. blitcp does none of these.

Questions

Is blitcp a replacement for rclone?

For some jobs. Both copy between local disks, SSH hosts and S3, Azure or Google Cloud Storage. rclone also reaches Google Drive, OneDrive, Dropbox and over 70 cloud products through their APIs, can sync with deletes and can mount a remote as a disk. blitcp is built around local and SSH copies: reading in disk order, verifying by default, and a native desktop app.

Does rclone have a GUI?

Yes: a web GUI bundled with rclone, started with the rclone gui command and served on localhost; rclone's home page calls it experimental. blitcp's desktop app is a native window on Linux, macOS and Windows.

Can blitcp copy to Google Drive, OneDrive or Dropbox?

Through the folder each service's desktop client keeps in sync, not through their APIs: blitcp verifies the copy into that folder and the client uploads it. rclone talks to those services' APIs directly.

Which one is faster?

We have not measured blitcp against rclone, so this page gives no number. The benchmarks page lists every comparison that has been measured.

Is blitcp free for commercial use?

Yes. blitcp is open source under the Apache-2.0 license, which allows commercial use, and has no paid tier. rclone is free software under the MIT license.
