blitcp vs FastCopy

blitcp is an open-source copy tool — CLI and desktop app — that moves a folder to another drive, a NAS, another machine or cloud storage and verifies every file arrived. FastCopy is a fast, highly tunable Windows copier. Here is where each one wins.

Use blitcp when

You want the copy verified by default, or you are on macOS or Linux as well and would rather learn one tool.

Use FastCopy when

You are on Windows only and want to tune buffer sizes and I/O behaviour yourself. FastCopy exposes far more knobs than blitcp does.

The measured difference

Same workload, same machine: 9,578 files / 890.8 MB, USB 2.0 external HDD to internal SSD (NTFS), Windows 11, full reboot before each run, Windows Defender active for both tools:

ToolTimeVerification
blitcp2 m 28 sON — every file hash-checked
FastCopy 5.113 m 38 soff

What blitcp gave up to post 2:28. It ran --no-dedup --no-cache, so neither deduplication nor the cross-run hash cache contributed anything, and verification was left on — every file read back from the destination and compared. FastCopy ran /verify=FALSE. blitcp finished more than a minute ahead with its own advantages switched off and its integrity check switched on, against a tool running without one. FastCopy for Linux and macOS?

FastCopy is a Windows program; there is no Linux version. RapidCopy, a separate port of FastCopy, is available for macOS. If you came here looking for it on Linux or a Mac, what you probably want is what it is known for on Windows — a fast copier for big folders that you can trust with a backup. blitcp runs natively on Linux, macOS and Windows:

  • Desktop app or CLI. A window for picking source and destination, or one command for scripts and cron. The same engine behind both, the same behaviour on every platform.
  • Verified by default. After a local copy every file is read back from the destination and hash-checked. In FastCopy verification is an option you turn on.
  • Reads in disk order. Files are read in the order they sit on the disk (FIEMAP on Linux, fcntl on macOS, FSCTL on Windows), which removes most of the seeking on a spinning drive.
  • Destinations FastCopy does not have. SSH hosts, S3, Azure and Google Cloud Storage, besides local drives and network shares.

What blitcp does not offer is FastCopy's depth of tuning: buffer sizes, I/O modes and filter syntax. If those knobs are why you use FastCopy, they are not here. Linux · macOS install notes.

When FastCopy is still the better tool

Honest answer: it's a 20-year-old, battle-hardened Windows native with Explorer integration and fine-grained include/exclude filters that many admins know by heart. If your world is Windows-to-Windows local and SMB copies and you rely on its filter syntax, it remains a fine tool. blitcp earns its place when you want the same job to also run on Linux servers and NAS boxes, push over SSH or to object storage, deduplicate, and hand you a hash-verified result by default.

Questions

Is there FastCopy for Linux or macOS?

FastCopy is a Windows program, with no Linux version; RapidCopy, a separate port of FastCopy, is available for macOS. blitcp runs natively on Linux, macOS and Windows, as a command-line tool and as a desktop app, with verification on by default on every platform.

When should I still use FastCopy?

When your copies are Windows to Windows, local or SMB, and you rely on its include and exclude filter syntax, Explorer integration, or its buffer and I/O tuning. FastCopy exposes far more knobs than blitcp does.

Which was faster in the benchmark?

On the same 9,578 files (890.8 MB) from a USB 2.0 drive to an SSD on Windows 11, blitcp took 2m28s with verification on and dedup off; FastCopy 5.11 took 3m38s with verification off.

Is blitcp free for commercial use?

Yes. blitcp is open source under the Apache-2.0 license, which allows commercial use, and there is no paid tier: the CLI and the desktop app are the whole tool.
